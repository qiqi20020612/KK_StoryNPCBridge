# KK_StoryNPCBridge 1.3.0

English | [简体中文](https://github.com/qiqi20020612/KK_StoryNPCBridge/blob/v1.3.0/docs/releases/1.3.0.zh-CN.md)

Changes since **1.2.0**.

## Added

- `adjust_stats`: add signed deltas to native scores and counters, including `favor`, `intimacy` and `lewdness`. Results are clamped to each field's legal write range and return the original values, actual values, effective deltas and clamped field names. Multi-field changes share the existing validation, native synchronization, persistence and failure rollback.
- Stable `mutationId` replay protection for adjustments. Retrying the same change in the same actor generation returns its original outcome without applying it twice, including after control recovery. Conflicting payloads are rejected.
- `sample_native_action`: independently choose another native girl's current task as an anonymous behavior reference on each call. Replies include action/map descriptions and reusable task requests, with no source character information. Sampling does not advance native AI or consume the game's random state.
- Native event effects for confession, breakup, H invitation, date booking and club admission. The event catalog now exposes 11 effects, retaining lunch, club activities, study, exercise, follow and going home together.
- Structured native-event requirements and effect snapshots before/after execution, including relationship/date state and applicable native ranking, player and club-report counters. Confession, date booking and admission apply accepted native state effects without opening or interrupting dialogue.

## Changed

- ADV replies now paginate with a shared width budget equivalent to **60 Chinese characters or 100 ASCII characters per page**. Mixed text uses the same budget; text-element boundaries and complete API history are preserved.
- Mouth opening is now read-only. `mouthOpen` writes are rejected; the plugin no longer sets mouth-opening limits or pins the opening rate. Mouth pattern selection remains writable.
- Native-event availability explicitly checks relationship, club membership, native time, date-slot and location conditions as applicable. Activity flows still use native ADV and game effects, without invitation/refusal rolls.
- `stat_catalog` identifies fields supporting adjustment and documents adjustment limits/replay policy. The manual client adds `adjust MUTATION_ID favor=4 intimacy=-2 lewdness=4`. English and Chinese API/reference guides cover the new operations and results.

## API notes

`set_stats` retains absolute assignment semantics and existing relationship/flag meanings. No emotion-rating rules or favor-to-intimacy conversion were added. `adjust_stats` requires a claimed actor, the current generation, `mutationId` and `deltas`; replay records are bounded to that actor generation. The transport protocol remains version `2`.

Install by replacing `BepInEx/plugins/KK_StoryNPCBridge.dll` while the game is closed, or extract the ZIP into the game directory. See the [API guide](https://github.com/qiqi20020612/KK_StoryNPCBridge/blob/v1.3.0/API.md) for request schemas, ranges, errors and retry behavior.
