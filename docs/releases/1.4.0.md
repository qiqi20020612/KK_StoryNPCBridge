# KK_StoryNPCBridge 1.4.0

English | [简体中文](https://github.com/qiqi20020612/KK_StoryNPCBridge/blob/v1.4.0/docs/releases/1.4.0.zh-CN.md)

Changes since **1.3.0**.

## Added

- `play_adv_sequence`: submit 1–32 ordered segments combining NPC/player lines, narration, expressions, loaded motions and delays. Runs one continuous native ADV list through the existing dialogue lifecycle, menu coordination and pagination.
- `adv_sequence_status`, `cancel_adv_sequence` and lifecycle events for progress, completion, cancellation and native execution failure. Unexpected disconnects pause progression and native delays; recovery continues without replaying completed segments. Cancellation and scene changes discard remaining fragments.
- Native expression controls for cheek blush (`blush`), tear mesh levels (`tears`), gaze modes (`gaze`), eye highlights (`highlight`) and eyebrow opening (`eyebrowOpen`), with live values, ranges and availability reasons.
- `expression_presets` and `expression_catalog.presets`: `neutral`, `smile`, `shy`, `crying`, `angry` and `surprised`. Apply a semantic key or returned entry through `set_expression.changes.preset`, optionally overriding individual fields. Patterns resolve from the current model's morph labels rather than fixed numerical IDs; unavailable or ambiguous combinations are rejected.
- Extended expression objects and presets in ADV sequence segments, using native CharaExpression and optional CharaFixMouth commands. Displayed sequence lines retain correct NPC/player/narrator identities and conversation ownership.

## Changed

- `mouthOpen` is writable again as a native opening **limit**. The separate `mouthFixed` boolean explicitly pins the mouth at that opening; false restores native mouth motion and lip sync. Setting the limit alone does not fix the mouth.
- Expression batches validate before any field changes. The live catalog exposes supported gaze references, parameter availability and reusable requests; actor replies report actual native values. Missing shaders, controllers or required tear meshes are reported rather than simulated.
- Extra expression overrides persist with each story profile. Clearing or releasing control restores captured native extra values, including mouth fixation. Sequence-only extra changes restore their prior values at completion/cancellation, while native activity takeover retains control of its own scene.
- English and Chinese API/reference documentation and manual client commands cover sequence execution, presets and additional expression controls. `say`, `say_native`, direct pattern selection and ordinary native events retain their existing roles.

## Usage limits

Sequences require the bridge NPC's already-ready native TalkScene; open it with `native_talk` or normal conversation first. Motions use the currently loaded Animator; refresh visual references after scene changes. Arbitrary ADV commands and animation bundle loading are not exposed.

`tears` is an integer level from `0` to `3`, not a continuous amount. Gaze supports native `FORWARD`, `TARGET` and `AWAY` modes using the existing native target. Arbitrary directions, angles or new target coordinates are not exposed; native `CONTROL` modes are explicitly unavailable. Blush respects the game's blush setting.

The transport protocol remains version `2`. Close the game before replacing `BepInEx/plugins/KK_StoryNPCBridge.dll`, or extract the ZIP into the game directory. See the [API guide](https://github.com/qiqi20020612/KK_StoryNPCBridge/blob/v1.4.0/API.md) for schemas, status/events and examples.
